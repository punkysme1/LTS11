# Audit Turots — 9 Oktober 2026

## Kesimpulan

Turots layak dilanjutkan sebagai katalog kuratorial manuskrip pesantren dan ruang baca digital. Implementasi yang diaudit masih merupakan prototipe fungsional: belum layak dianggap sebagai infrastruktur penelitian yang menjamin ketepatan bukti, sinkronisasi aman, dan sitasi halaman yang dapat direproduksi. Prioritasnya ialah integritas hubungan objek fisik–unit teks–Canvas–citra–klaim, sebelum perluasan fitur.

Penilaian memakai perspektif filologi dan humaniora digital, skill code-reviewer dan ui-ux-pro-max, pemeriksaan kode, migrasi SQL, dokumentasi, build, skrip verifikasi, contoh uji parser, dan observasi browser lokal. Tidak ada kode aplikasi atau data katalog yang diubah untuk audit ini.

## Cakupan dan batas bukti

- Entry point aktif: `src/main.tsx` mengimpor `AppV11`; `App.tsx`, `AppV1.tsx`, serta `legacy-*` bukan bukti fitur aktif.
- Database terkait: `Services/Supabase/turots-local/supabase/migrations` dan fungsi `nawra-catalog`, di luar folder aplikasi.
- Turots lama diperiksa melalui schema, server, komponen dan dokumen salinannya. Ini bukan audit deployment lama yang sedang berjalan.
- Build produksi berhasil setelah mengatasi batas realpath sandbox Windows. Bundle JavaScript sekitar 510,41 kB, gzip 145,75 kB; Vite memperingatkan ukuran chunk.
- `verify:v11`, `verify:v1`, `verify:nawra` lulus. Dua terakhir terutama memeriksa teks/file; v11 mencampur render komponen, fungsi metadata, dan pencocokan source. Kelulusan tidak membuktikan alur data end-to-end.
- Browser lokal menampilkan beranda, navigasi mobile, pencarian dan filter. Katalog akhirnya menampilkan kegagalan pemuatan, sehingga pemeriksaan detail dengan data nyata, sesi admin, RLS efektif dan konsistensi produksi belum dilakukan. Penyebab infrastruktur belum dipastikan.
- Uji sintetis mengeksekusi fungsi parser yang diekstrak dari source: manifest v3 Archive menghasilkan label fallback dan URL citra rekaan; manifest v2 eksternal kehilangan URL resource `@id`. Uji fungsi metadata mengonfirmasi ketidakcocokan field provenance dan hilangnya nilai ukuran parsial.

## Archive dan IIIF

Implementasi sekarang mengambil manifest, mengambil metadata Archive, menyaring semua JPG/JPEG/PNG kecuali `_thumb`, mengurutkan nama secara numerik, lalu memasangkan berdasarkan posisi. Manifest tidak digunakan sebagai otoritas pemetaan citra. `label` bahkan dipakai sebagai nama file pada fallback Archive. Label merupakan teks tampilan, bukan kunci berkas.

Kasus berisiko meliputi file sampul tambahan, citra turunan, urutan scan yang berbeda dari nama file, manifest dengan label folio, gambar TIFF/JP2, halaman dari PDF, atau file yang ditambah belakangan. Jumlah Canvas dan file yang sama pun tidak membuktikan pemetaan benar. Format selain JPG bukan otomatis harus diunduh; layanan Image API dapat menyajikan turunannya.

Parser juga mengasumsikan satu annotation page, satu annotation dan satu body. Belum ada pemeriksaan type/motivation, language map, Choice, multiple bodies, image service, width/height, rights, requiredStatement, viewingDirection, ranges, timeout, retry terkendali, cache, hash sumber, job history atau pemulihan impor. URL IIIF non-Archive tetap dibawa ke lookup metadata Archive. Input identifier/URL belum menjadi kontrak provider yang jelas.

Strategi yang direkomendasikan:

1. Kenali input secara eksplisit: Archive identifier, URL item Archive, atau manifest IIIF eksternal.
2. Ambil manifest dan metadata sumber dengan batas waktu, batas ukuran, cache serta klasifikasi error. Jika dilakukan backend, batasi skema/host atau terapkan perlindungan SSRF dan redirect.
3. Simpan snapshot mentah, URL, waktu, hash dan versi parser. Metadata sumber tetap dapat ditelusuri.
4. Normalisasi Presentation 2/3 ke model internal. Urutan berasal dari Canvas; citra berasal dari painting annotation/body/service.
5. Untuk Archive, file metadata adalah sarana rekonsiliasi. Cocokkan identitas file eksplisit; periksa original/derivative dan checksum bila tersedia. Jangan cocokkan melalui indeks.
6. Tandai pemetaan ambigu atau sumber belum siap sebagai status yang perlu ditinjau. Jangan menebak dan melaporkan sukses.
7. Beri layar pratinjau Canvas–citra–folio–unit sebelum commit, termasuk daftar item tak cocok dan perubahan urutan.
8. Simpan transaksi secara atomik dan idempoten. Retry job yang sama tidak membuat duplikasi atau menghapus kurasi.
9. Pisahkan sinkronisasi sumber dari edit metadata. Tampilkan diff; tambahan, penghapusan dan perubahan citra membutuhkan keputusan yang tercatat.

Setelah pemetaan dapat dipercaya, Turots dapat menerbitkan manifest kuratorialnya sendiri dengan URI stabil, identitas Canvas internal, metadata yang disetujui, atribusi dan ranges unit teks; media tetap dapat dilayani Archive. Ini rekomendasi arsitektur, bukan fitur yang sudah ada. IIIF Presentation dapat memuat citra statis; masalah viewer sekarang bukan semata tidak memakai tile, melainkan kontrol zoom, performa dan provenance yang belum memadai.

## Sinkronisasi dan tata kelola metadata

Saat ini ada beberapa representasi: tabel legacy `manuscripts`, tabel `turots_*`, metadata Archive, JSON pada kolom text, dan tabel provenance terpisah yang tidak dipakai jalur editor aktif. Belum ditemukan mekanisme merge tiga arah, kepemilikan field, konflik, maupun revisi yang menghubungkannya. Kehadiran tabel audit tidak sama dengan audit trail yang terisi otomatis; jalur write yang ditinjau tidak menulisnya.

Pisahkan kewenangan:

| Data | Otoritas yang disarankan | Aturan pembaruan |
|---|---|---|
| File, URL asal, checksum sumber | Provider digital | Sinkronkan sebagai fakta teknis; simpan snapshot |
| Urutan Canvas sumber | Manifest sumber | Pertahankan sebagai urutan sumber; perubahan harus direkonsiliasi |
| Foliasi kuratorial dan batas unit | Kurator Turots | Jangan ditimpa refresh Archive |
| Judul, atribusi, tarikh, relasi | Klaim kuratorial bersumber | Revisi dan konflik eksplisit |
| Nilai katalog lama | Snapshot legacy | Bukti historis, bukan penimpa otomatis |
| Publikasi dan hak akses | Pengelola koleksi | Keputusan eksplisit, terpisah dari impor |

Merge membandingkan snapshot sumber sebelumnya, sumber terbaru dan nilai lokal. Jika lokal sudah dikoreksi dan sumber berubah berbeda, buat konflik. Simpan siapa, kapan, alasan, nilai lama/baru, locator dan keputusan. Gunakan revision/version untuk mencegah penimpaan antar-editor. Sediakan rollback revisi dan export data terbuka.

Bridge legacy saat ini memindahkan sebagian field identitas/isi, tetapi tidak seluruh kodikologi, ukuran, kondisi, halaman dan hubungan. Ia juga menyatukan sumber dalam koleksi `Katalog Turots lama` dan tidak menyediakan tabel pemetaan kategori legacy. Ini risiko kehilangan konteks pada katalog baru, bukan bukti data legacy terhapus. Migrasi lanjutan perlu laporan coverage per kolom, nilai tak terpetakan, duplikasi, dan rekonsiliasi hitungan.

## Model filologis

Pemisahan bendel dan unit teks merupakan fondasi yang tepat, tetapi implementasi belum menjalankan konsekuensinya. Save baru memaksa ID bendel sama dengan display ID unit, membuat `sequence_no:1`, dan menautkan semua halaman ke unit itu. UI tidak menyediakan pemecahan/penambahan unit pada bendel yang sama. Page hanya memiliki satu `text_unit_id`: dua teks dalam satu halaman atau unit mulai di tengah halaman belum terwakili.

Model bertahap yang lebih memadai: koleksi → objek fisik → bagian kodikologis bila diperlukan → unit teks sebagai saksi karya; objek fisik mempunyai reproduksi digital → Canvas → region; unit teks menunjuk rentang Canvas/region. Karya intelektual dan salinan fisiknya perlu dibedakan agar matan, syarah, hasyiyah dan salinan lain dapat dihubungkan tanpa menyamakan semuanya sebagai “manuskrip”.

Metadata fisik sebaiknya melekat pada objek atau bagian yang tepat. Menaruh jilid, kover dan ukuran hanya pada unit teks berisiko menghasilkan deskripsi fisik yang saling bertentangan untuk satu bendel. Jumlah folio, halaman bernomor dan jumlah foto harus terpisah; penjelasan form tentang perbedaan lembar dan foto sudah baik.

Kebutuhan ilmiah berikut belum memadai pada alur aktif:

- Incipit, explicit, kutipan diplomatik kolofon, lokasi bukti dan alternatif identifikasi judul.
- Atribusi pengarang/penyalin dengan dasar dan tingkat kepastian; jangan menyamakan dugaan dengan fakta.
- Tarikh asli, kalender, rentang normalisasi, cara konversi dan ketidakpastian.
- Bahasa/aksara jamak serta varian/alias. Pilihan tunggal sekarang tidak cukup untuk Arab–Jawa, Pegon, Jawi dan Melayu; nilai legacy di luar daftar tampil seperti belum dipilih.
- Kolasi kuras, perubahan tangan, foliasi berbeda, lacuna, urutan rusak dan bagian tambahan, sesuai kebutuhan koleksi.
- Authority record untuk tokoh/tempat/karya dan relasi berbukti; isian bebas saja tidak mendukung rekonsiliasi nama.
- Bedakan “tidak ada”, “belum diperiksa”, “tidak diketahui”, dan “tidak berlaku”.

Gunakan TEI sebagai acuan konseptual dan jalur ekspor; tidak perlu memaksa semua penyimpanan menjadi XML. Prioritaskan data yang benar-benar diperlukan penelitian koleksi Qomaruddin.

## UI dan workflow

Observasi visual: palet hijau-krem dan tipografi memberikan identitas yang sesuai koleksi; navigasi mobile serta label pencarian tersedia. Teks pengantar dan ornamen menghabiskan hampir seluruh viewport awal. Kategori tersembunyi di strip horizontal; daftar kategori yang dapat dicari akan lebih mudah dijelajahi. Nama Turots, Sampurnan dan Qomaruddin perlu dijelaskan relasinya. Menu “Profil” sebenarnya profil lembaga, bukan akun; “Tentang koleksi” lebih jelas.

Katalog menampilkan `0 unit` walau request gagal. Bedakan belum termuat, kosong sungguhan dan gagal. Tambahkan status tanpa angka semu. Kartu mengambil thumbnail awal bendel untuk setiap unit, bukan halaman pembuka unit: perbedaan unit menjadi kabur. Favorit lokal sudah dijelaskan, tetapi pagination favorit mengarah ke `/katalog` dalam source.

Viewer memerlukan jump ke folio, previous/next, keyboard, rotasi, fullscreen, arah baca, indikator gambar rusak serta tautan halaman stabil. Thumbnail memakai URL gambar penuh pada impor dan semuanya dirender di strip tanpa lazy loading. Riset memerlukan perbandingan dua saksi, sitasi halaman/region dan anotasi; ini tahap setelah sumber dan viewer dasar beres.

Form kuratorial terlalu bergantung pada keberhasilan impor gambar. Metadata seharusnya dapat disimpan tanpa citra. Pisahkan tahap identifikasi sumber, rekonsiliasi halaman, identitas fisik, unit teks, deskripsi dan review. Tombol simpan/fetch belum memiliki busy state yang mencegah request ganda; error global belum ditautkan ke field. Tambahkan perlindungan perubahan belum disimpan dan draft yang dapat dilanjutkan.

Alur yang disarankan: daftarkan sumber → validasi teknis → simpan draft atomik → petakan folio/unit → kurasi metadata → review bukti dan hak akses → publish → revisi berversi. `review` sudah ada sebagai status skema, tetapi tombol Publish langsung mengubah bendel menjadi published tanpa pemeriksaan kelengkapan. Satu tombol unit juga mempublikasikan seluruh bendel, sehingga ruang lingkupnya perlu jelas.

Hapus unit sekarang hard delete; FK halaman menjadi null dan viewer hanya memilih halaman yang terkait unit. Halaman dapat tersisa tetapi hilang dari jalur baca. Sediakan arsip/undo dan pemeriksaan dependensi sebelum penghapusan.

Aksesibilitas memiliki fondasi positif: aria-label pencarian/favorit, aria-pressed, focus ring, dan beberapa status live. Belum ada audit screen reader/keyboard menyeluruh atau pengukuran kontras semua komponen. Jangan mengklaim lulus WCAG dari audit ini. Error form, label status, ukuran teks metadata kecil, pengelolaan fokus ketika navigasi SPA, dan reduced motion perlu pemeriksaan lanjutan.

## Struktur dan rekayasa

Folder aplikasi mencampur tiga generasi App, komponen legacy, demo, konsep, SQL awal, migrasi parsial dan CSS override. Entry point jelas, tetapi dokumentasi README masih menyebut blueprint dan placeholder. Schema konseptual menggunakan `physical_bundles/text_units`, sedangkan runtime memakai `turots_bundles/turots_text_units`. Migrasi utama dan edge function berada di folder Services; menyalin aplikasi saja tidak menghasilkan deployment yang dapat direproduksi.

Kelompokkan secara bertahap, tanpa rewrite besar:

```text
src/app/                    routing dan layout
src/features/catalog/       pencarian dan kartu
src/features/reader/        viewer, halaman dan sitasi
src/features/curation/      editor dan review
src/domain/                 tipe serta aturan filologis
src/integrations/iiif/      parser dan normalisasi
src/integrations/archive/   adapter sumber
src/data/                   repository dan kontrak DB
supabase/migrations/        satu rangkaian otoritatif
supabase/functions/         fungsi aplikasi
tests/fixtures/             kasus manifest dan metadata
docs/                       keputusan, kamus data, operasi
```

Banyak `any`, mapper manual, fungsi padat satu baris dan CSS bertumpuk mempermudah kontrak field menyimpang. Gunakan tipe DB yang konsisten, validasi runtime di batas impor, mapper bersama dan komponen per tanggung jawab. Routing detail harus query slug/id tepat, bukan mengambil seluruh katalog lalu menebak judul. Admin dan reader dapat dimuat terpisah untuk mengurangi bundle awal.

Bangun uji perilaku untuk IIIF v2/v3, label multibahasa, file ekstra, urutan berubah, dua unit satu folio, kegagalan di tengah transaksi, round-trip metadata, slug Arab/duplikat, pencarian hasil lama, konflik edit, dan matriks hak akses. Build saat ini tidak menjalankan typecheck eksplisit; tambahkan pemeriksaan tipe dan CI bersama pengujian yang relevan. Jangan mempertahankan assertion yang hanya mengabadikan implementasi keliru.

## Operasional dan preservasi

Internet Archive berguna sebagai penyedia akses, tetapi belum ada bukti audit ini tentang kebijakan master preservasi, jumlah replika, fixity berkala, atau keberhasilan restore Turots. Adanya folder backup tidak membuktikan dapat dipulihkan. Tetapkan inventaris master, checksum, cadangan metadata+mapping+provenance, ekspor terbuka, pemilik operasional dan uji pemulihan berkala. Perubahan URL provider tidak boleh merusak identitas sitasi internal.

Hak akses harus berlaku di backend dan media delivery. Menyembunyikan tombol tidak membatasi file Archive publik. Pisahkan izin publikasi metadata, izin akses citra, lisensi penggunaan, atribusi pemilik dan sensitivitas koleksi menurut kesepakatan pengelola. Audit belum menguji konfigurasi produksi; temuan kebijakan akses adalah temuan source yang perlu diverifikasi terhadap DB efektif.

## Urutan pengerjaan dan kriteria selesai

1. **Baseline dan pengamanan data.** Inventaris schema/runtime, backup yang diuji, akses DB, snapshot sumber dan aturan field. Selesai bila deployment yang diaudit diketahui, data dapat dipulihkan, dan tidak ada impor ulang yang diam-diam menimpa kurasi.
2. **Integritas impor.** Parser v2/v3, pemetaan identitas eksplisit, staging, transaksi dan retry idempoten. Selesai bila contoh file ekstra/urutan berbeda tidak menghasilkan citra salah; gagal di tahap mana pun tidak meninggalkan draft rusak.
3. **Round-trip dan sinkronisasi.** Perbaiki mapper/provenance/dimensi/editor tanpa halaman, pisahkan refresh sumber, revisi dan konflik. Selesai bila semua field dapat disimpan–dibuka ulang–ditampilkan tanpa kehilangan makna dan dua editor tidak saling menimpa diam-diam.
4. **Keterbacaan dan penemuan.** Slug tepat, viewer zoom sebenarnya, thumbnail, query per objek, pencarian server, keadaan error. Selesai bila tautan katalog selalu membuka unit yang dimaksud dan hasil di luar batas awal dapat ditemukan.
5. **Kurasi ilmiah.** Multiunit, rentang/region, foliasi, klaim alternatif, review dan sitasi. Selesai bila bendel majemuk dapat dijelaskan tanpa menggandakan objek fisik dan kutipan dapat kembali ke bukti tepat.
6. **Interoperabilitas dan keberlanjutan.** Manifest kuratorial, ekspor TEI sesuai kebutuhan, anotasi, perbandingan saksi dan monitoring. Tentukan volume data, anggaran serta kapasitas kurator sebelum estimasi biaya/waktu.
